%--Abstract
\begin{abstract}
A web application firewall judges each request based on its content. Deception is usually done after a session has already been judged hostile. Our approach uses it while the decision is uncertain. When system is not sure, it adds invisible probes to response. These are not shown in browser but the client that acts on it reveals itself. The decision to probe is based on the value of information it provides rather than manual thresholds. Under the usual cost model, there is no middle option between passing and diverting. The probing band appears only once the information is priced. In randomised comparison over 99 runs, probing increases the share of attacks caught by 7.0 percentage points and no harmless sessions was diverted.

\keywords{Cyber deception \and Intrusion detection \and Web application security \and Value of information \and Cost-sensitive learning \and Honeytokens}
\end{abstract}

%  1 introduction
\section{Introduction}

Accepting or rejecting a request is in the hands of the firewall. It makes decision on the information the request carries. Act early on weak evidence can block real user. If wait for strong evidence, the attacker has already sent several requests. It makes an trade off. Learned detectors \cite{kruegel2003anomaly,tekerek2021novel} solve the problem to a degree, but they still watch, wait, and then commit.

Some attacks make it  worse. A request for \texttt{/records/5} looks similar for \texttt{/records/6}. If that record belongs to someone else, the request is an attack. There is no pattern to match for this, so a signature firewall is blind. A learned detector also struggles because an reporting tool walks the same ids in the same order, and nothing in the traffic separates the two.

Deception is the route around that blind spot \cite{pawlick2019taxonomy,provos2004honeyd}, but most systems use it after the decision is taken: a session is deemed hostile, and the response to it is the activation of a honeypot. We put the deception before that decision is taken. While a session is still in doubt, its replies would carry something extra. A browser would never show it, but anyone reading the raw response will see it. It can be a fake database error naming a table that does not exist, or an unused field in a JSON reply. We call these additions \emph{probes}. An honest user will not notices, while a attacker that acts on that probe reveals itself.

A probe can be engineered. Our objective is to find out \emph{when} to use that probe. A probe buys no protection, because the request still reaches the application. Its only value is the information it might reveal, and that value can be priced \cite{howard1966information}.

\paragraph{Contributions.} This paper makes two contributions.
\begin{enumerate}
\item \textbf{A priced third action.} Probing costs more than passing at every belief, so under ordinary cost accounting there is no band for a threshold to create. The band appears only once the information a probe buys is priced, which makes its edges follow from the cost table rather than from a choice of ours.

\item \textbf{A measured causal effect.} Inside the probing system, we withhold the probe from one session in ten, chosen at random, so its effect is a randomised estimate rather than a comparison of two different designs.
\end{enumerate}

\section{Literature Review}
We group previous work into five areas and find the gaps in them.

\paragraph{Detecting web attacks.} Signature firewalls matches known bad patterns. Thus attacks written in valid syntax can bypass it. Also, known payloads can be changed to avoid a match. Learned detector replaces fixed patterns with a model. Kruegel and Vigna \cite{kruegel2003anomaly} built early anomaly detector for web request. Robertson et al. \cite{robertson2006generalization} apply this to multiple sites. Later, adaptive \cite{amouei2022rat} and deep \cite{tekerek2021novel} method was applied. All these systems observe session, collect evidence and make decision. Our system follow this and is not our contribution. 

\paragraph{Detect automated clients.}  Next, is to detect client is automated rather than finding if it is harmful. Iliou et al. \cite{iliou2021detection} tells about advance bots. These can behave same as real browsing which make difficult to distinguish them from automated bot. Thus, we measure automation and hostility separately. An automated scanner is both automated and hostile, price comparison bot is only automated. A human attacker is hostile but not automated. Thus, a single score can't distinguish between these cases.

\paragraph{Deception and honeytokens.} Deception is widely studied as defense. Provos \cite{provos2004honeyd} built an early virtual honeypot framework. Almeshekah and Spafford \cite{almeshekah2014planning} suggests that it should be planned around target belief. Pawlick et al. \cite{pawlick2019taxonomy} classified different deception approaches. Beltr\'an-L\'opez et al. \cite{beltran2025cyberdeception} reviewed recent deception research and Ferguson-Walter et al. \cite{fergusonwalter2021examining} studied how deception affects attackers and found that this can disrupt their actions. In all these works deception is a place where caught attacker is moved. Tripwires are been used for long time, including honeyfiles \cite{yuill2004honeyfiles}, decoy documents \cite{bowen2009baiting}, fake passwords \cite{juels2013honeywords}. These are usually kept active always. Kahlhofer and Rass \cite{kahlhofer2024applayer} reviewed different ways to deploy inside application without access of source code. Kahlhofer et al. \cite{kahlhofer2025koney} automate the deploy and rotating trap, but didn't tell when to place. These traps can be detected. Honeypots \cite{vetterl2018bitter} and honeytokens \cite{srinivasa2020honeytoken} can be detected using fingerprinting techniques.


\paragraph{Generated fake environments.} Language models can be used to fabricate a system that can be presented as a real one to the user. Sladi\'c et al. \cite{sladic2024shellm} dynamically create shell output. Bridges et al. \cite{bridges2025sok} summarise the area and conclude that the progress made so far is limited. Such work measures how enticing a planted item is \cite{kahlhofer2024honeyquest}, and Vero et al. \cite{vero2026honeyval} add stealth and fidelity. None of it asks if a fake system contradicts itself during a long visit. This is what we test. Our fake site is also constructed such that its content generator can be swapped, which lets us check that the result is not dependent on the production of the content.

\paragraph{Decision theory.} The mathematics that underlies our approach is standard. The value of sample information was introduced by Howard \cite{howard1966information}. Elkan \cite{elkan2001foundations} described cost-sensitive decisions using a loss matrix, and Axelsson \cite{axelsson2000baserate} showed how the rarity of attacks limits the performance of intrusion detectors. There is also work that looks at transforming the output of the classifiers to provide probabilities \cite{zadrozny2002transforming}. There is no action in any of them leading to the purchase of evidence. This is the gap. There is no new mathematics here. We can only add to it by recognising a probe as a purchase of information, and by pricing it to turn the hand-chosen option into a calculated choice.

\section{Methodology}

\subsection{System Overview}
Our system is reverse proxy in front of real web application. Client only talk to proxy. Each request goes to application through proxy only. This let application never knows that deception exists. 

Each request follows the five steps.
\begin{enumerate}
\item Identify the session using a cookie.
\item Turn the request into 18 features.
\item Update two scores of the session.
\item Price the three possible actions and take the cheapest.
\item Write the decision to a untampered log
\end{enumerate}

The three actions are \emph{pass}, \emph{probe} and \emph{divert}. Pass send the request to real application, Divert moves session to the fake copy and probe adds probe to response and passes the request on unchanged. 

\subsection{Two Scores}
The 18 features are split into two groups because threat has two parts. There are ten \emph{automation features} which tells how the client behaves. This include time between request, how regular timing is, whether static assets were fetched, how complete headers are and whether cookie was sent. The eight \emph{hostility features} describes what client is trying to do. It measure unusual character in user input, failed logins, database keyword in suspicious position, ratio of errors to replies and how many different account the session tried to reach. We used two logistic models which turn these features into two scores. Both scores are build up as session continues. We kept them separate because automated client can be completely harmless. So, hostility tells whether we should take action and automation score helps decide which probe to use, since human and automated client respond different to different bait.

The belief is not a calibrated probability, its a score. On held out data calibration error is 0.157. This is been reduced to 0.018 by using isotonic map \cite{zadrozny2002transforming}. We haven't apply this map because under fixed cost table it performs worse. The gain in recall comes from diverting harmless clients. The bands derived below treat the score as probability. Section~\ref{sec:discussion} discusses the drawback of this assumption.

\subsection{Choosing Action by Price}

The system continuously maintain a belief $p$ whether client is hostile. Each action has a cost, defined by loss matrix \cite{elkan2001foundations}. We hashed and fixed these cost before collecting data so no threshold derived from them could be adjusted afterwards to improve results. The cost used in our system are shown in Table~\ref{tab:costs}.

\begin{table}[t]
\centering
\caption{The fixed cost table.}
\label{tab:costs}
\begin{tabular}{@{}lrrr@{}}
\toprule
 & pass & probe & divert \\
\midrule
client is harmless & 0  & 1  & 200 \\
client is hostile  & 25 & 25 & $-20$ \\
\bottomrule
\end{tabular}
\end{table}

Three numbers in Table~\ref{tab:costs} tells main trade offs. Diverting harmless client is worst decision, so it costs 200. Probing an hostile client and passing it through are both set to 25 as the request still go to real application in either case. Probing harmless client adds small extra cost of 1.

Using these, the expected cost of each action is straight line in $p$:

\begin{equation}
\mathbb{E}[C_{\text{pass}}] = 25p, \qquad
\mathbb{E}[C_{\text{probe}}] = 24p + 1, \qquad
\mathbb{E}[C_{\text{divert}}] = -220p + 200.
\label{eq:costs}
\end{equation}

Compare first two terms of Equations~(\ref{eq:costs}):
%
\begin{equation}
\mathbb{E}[C_{\text{probe}}] - \mathbb{E}[C_{\text{pass}}] = 1 - p \;\geq\; 0 .
\label{eq:gap}
\end{equation}

The gap in Equation~(\ref{eq:gap}) is $1-p$. This can never be negative. This means probing is never cheaper than passing. It would only choose between passing and diverting. The switch between two occurs when $25p = 200 - 220p$, at $p \approx 0.816$. This may seems probing band was chosen manually but this is not the case. At this stage, there is no band to choose. 

\subsection{Pricing the Information}
Probe is useful because of the information provided. It has two outcomes: client takes bait or it does not. This outcome gives extra information about the client. We measure this with expected value of sample information \cite{howard1966information}:

\begin{equation}
V(p) = \min_a \mathbb{E}[C(a) \mid p] \;-\;
       \mathbb{E}_Z\!\left[ \min_a \mathbb{E}[C(a) \mid p'(Z)] \right].
\label{eq:evsi}
\end{equation}

In Equation~(\ref{eq:evsi}), $Z$ is what we observe and $p'(Z)$ is updated belief after seeing it. Let $\beta_a$ be probability a hostile client takes the bait, and $\beta_b$ be probability a harmless client does. Thus, the probability of bite is $p\beta_a + (1-p)\beta_b$ and we update our belief using Bayes' rule. Every term in Equation~(\ref{eq:evsi}) is straight line, so $V(p)$ can be calculated directly. No need of simulation. $V(p)$ prices one probe at a time. We do not plan a sequence of
them.

Earlier probe was never worth taking but now with information priced, its worth taking. So probe real value is cost minus value of the information. The system now picks cheapest of all three actions:
%
\begin{equation}
\text{price}(\text{probe}) = 1 + 24p - V(p).
\label{eq:price}
\end{equation}

Two things fix the band at two end. First, $V(p) \ge 0$ always. The smallest of several straight lines is concave. Jensen's inequality tells us that learning from the probe cannot increase the expected cost. Thus, information can only help or leave the decision unchanged. Second, $V(0) = V(1) = 0$: when we already know that client is hostile or harmless, probe can't change the decision. So, probing band is away from both end. The width is determined by cost and measured bite rate. It is not set by manual chosen threshold.

Equation~(\ref{eq:price}) gives:
%
\begin{equation}
\text{pass if } p < 0.065, \qquad
\text{probe if } 0.065 \le p < 0.879, \qquad
\text{divert if } p \ge 0.879 .
\label{eq:bands}
\end{equation}

Equation~(\ref{eq:bands}) changes the divert point. It pushes the point up from 0.816 to 0.879. System that can probe waits longer than one that cannot. We did not aim for this. This value is from the calculation. 

\subsection{Measuring the Probe and Tools Used}
\label{sec:tools}

The calculation above need one measured input i.e. how often each type client takes bait. We measured this separately after probe is been built. We locked the values before evaluation began. For main probe, 138 out of 183 hostile session took bait while none of 74 harmless sessions did. We converted these counts to rates using  posterior mean with Jeffreys Beta$(\tfrac12,\tfrac12)$ prior. It gives $\beta_a = 0.753$ and $\beta_b = 0.0067$. The smoothing is important for $\beta_b$. Without this, zero bites observation would produce infinite likelihood ratio and would suggest that harmless client can never take bait, which is strong conclusion to draw from 74 sessions.

All detection code, features, decision rule and experiments are our own written in Python. No language model is used in the request path or for data processing, filtering, visualisation or proving any result. 
Language models are used in three places. 
\begin{itemize}
\item \textbf{Simulated attackers:} We use three local models -- Llama 3.2 1B, Llama 3.2 3B, and Qwen 2.5 7B. This help to simulate the attack. Each model read the reply and chose next request without being told that probes exist. This test our assumption how curious attacker might interact with system.
\item \textbf{Content generation:} It help to generate content of fake site, allow us to test if the consistency layer depend on how content is created. When consistency layer was enabled, the fake site shows no contradiction across all 15 entities. Without the layer, all 15 entities contains contradictions. 
\item \textbf{Adversarial testing:} We attacked our own system using language model and look for weaknesses. This help to uncover several flaws in fake site, which we fixed and reported in Section~\ref{sec:discussion}.
\end{itemize}


\subsection{Experimental Setup}
We compare three systems:
\begin{itemize}
\item \textbf{B1} (\texttt{b1\_rules}): a signature firewall using fixed patterns.
\item \textbf{B2} (\texttt{b2\_passive}): our detector without probes. It can only pass or divert.
\item \textbf{B4} (\texttt{b4\_full}): the full system, with probes and the fake site.
\end{itemize}

B2 and B4 are same codes and same locked model. Configuration flag selects which of the two runs. B1 is independent signature baseline. We also evaluated two more systems which are not been reported as separate arms. Those are undefended arms and B3. B3 is based on approach from prior work. It cannot produce different values from B2 for both reported metrics because decoy only changes the response seen by diverted session and does not change the diversion decision.

We ran each system on 99 independent rounds of generated traffic. Each contains 120 attack sessions and 80 harmless sessions. This gives total of 11{,}880 attack sessions and 7{,}920 harmless sessions per system. In one round, all three system gets the same traffic so that attack session can be compared. This is 60\% attack rate, far more than any real deployment. The band edges do not depend on it. They are determined by cost table and bite rates. How often a session reaches the band does, so our result is measured under a prevalence no production site would see.



Throughout, \emph{diverted} means system had decided that client is hostile. We applied this across all system, so that numbers are comparable. Our evaluation follows the evaluation guidance for machine learning in security \cite{arp2022dos,sommer2010outside}: comparison are paired, costs are fixed and attack rounds used for training and testing the detector are kept separate.

\section{Results}
\label{sec:results}

\subsection{What the Probe Itself Causes}
B2 and B4 are two systems which differ in the probe and in the divert point that offering it moves. To isolate effect of probe, we ran comparison inside B4. We randomly select one in ten sessions that reaches the probing band and did not show them a probe. Both had same belief state and follows same rule. Only difference was if a probe was sent or not. Result are shown in Table~\ref{tab:holdout}.

\begin{table}[t]
\centering
\caption{The randomised comparison inside the full system.}
\label{tab:holdout}
\begin{tabular}{@{}lrrr@{}}
\toprule
group & sessions & caught & rate \\
\midrule
probe sent      & 10{,}643 & 10{,}112 & 0.950 \\
probe withheld  & 1{,}237  & 1{,}089  & 0.880 \\
\bottomrule
\end{tabular}
\end{table}

Table~\ref{tab:holdout} shows a difference of \textbf{7.0 percentage points}. The 95\% confidence interval is $[5.2, 8.8]$, and Fisher's exact test gives $p = 3.4 \times 10^{-19}$. Since two group were randomly separated at the same belief state, the probe caused the difference.

We also check for the random split balance. The largest difference in composition of two group across the five attack types is 1.2 percentage points. A chi-square test gives 2.58 with four degrees of freedom, which is below 9.49 threshold. This tells that split was well balanced. An uneven split may have introduced differences due to attack type mix rather than effect of probe.

\begin{tabular}{@{}llr@{}}

Table~\ref{tab:baselines} shows that B4 performs better than B2 on both recall and harmless diversions. The recall ranges for both systems are not overlapping. When we compare the same session in both systems, B4 catches 842 attacks that B2 misses, while B2 catches 197 that B4 misses. A paired test gives $p = 1.9 \times 10^{-95}$. B4 perform better in all 99 rounds.

Those 197 that B4 misses are delays, not noise. Their belief score was between 0.816 and 0.879, where B2 diverts immediately while B4 first asks a question. Some of the session ended before question is answered. That is the real cost of having a third action.

Both zero values should be explained. B1 rely on suspicious syntax that are not seen in harmless traffic. B4 result is interesting. All four harmless sessions that B2 divert wrongly were probed by B4. None of these took the bait. Their lack of response kept their belief below 0.879, while B2 had diverted them at 0.816. Four session are too few to conclude that B4 is safer but result tells how the mechanism can reduce unnecessary diversions.

obfuscated payload leaves a trace in the request itself, so the belief is seldom in
doubt, and a probe that confirms what the meter already knows has no effect on the
decision. The gain is small due to the lack of uncertainty remaining.



%  5 discussion
\section{Discussion}
\label{sec:discussion}

Our results are consistent with the mechanism and not just a number. If the probe had raised recall throughout, it would indicate a poor detector, not a proper calculation. But rather, the gain is sitting where the decision is in doubt, where the pricing indicates. The safety result looks like the same thing. Its divert point is not something we introduced, and its job was to fix all the mistakes made by the simpler detector.

\paragraph{Where our approach does not win.} If expected cost is the only measure, it is better to set the band edges by hand than to compute them. More than half of decisions can be made using two belief values, and the additional precision of a calculated edge does not really help. All settings that perform better than it do so by diverting harmless clients. Our calculated edges are the best that can be obtained in settings that do not divert anyone.

\paragraph{Adversarial testing of the fake site.} A language model agent attacking our own system (Section~\ref{sec:tools}) discovered four ways to tell the fake site from the real one, all of which were found by exploiting the fix for the previous method. A page returned other values following a diversion. A list page named a person differently from their own profile page. After a diversion there was a record which had not existed before. The bogus dashboard showed another user's records as the client's own. Then a human subject found a fifth, two profiles with the same name but different information. All five are fixed. The lesson generalises. A fake site agreeing with  itself is not the same as agreeing with what the attacker saw. That is a different failure from the fingerprinting of deployed decoys \cite{srinivasa2020honeytoken,vetterl2018bitter}, which reads the artefact instead of
its history.

\paragraph{Do people notice the fake site?} In a small-scale blind study, participants were randomly divided into two arms, the real and the fake application. The assignments were done in a block-randomised fashion with a fixed seed. One of the two called the fake site a mock-up, and one of the two called the real application a mock-up. The difference is zero and Fisher's exact test gives $p = 1.0$, but no $p$ below $0.333$ was reachable at this size, so that number means nothing by itself. Showing the two arms are alike is an equivalence question \cite{schuirmann1987comparison} and requires the eight participants our protocol asks for. The study does provide a baseline. One of the participants who studied the \emph{genuine} application called it a ``mock-up'' because of the way the staff directory was organised, putting together three departments and leaving a fourth one out. Real systems are called fake by people because of an ordinary layout quirk, and the correct baseline is not zero. This is reported as a pilot and not a result.

\paragraph{Who actually takes the bait?} This is not a steady increase of bite rate as the attacker's ability grows, and that is what bounds our central claim. When it gets stronger in the three local models it rises from 0.077 to 0.556. At both extremes outside, it is equal to zero. Replies were never read by the off-the-shelf tools. Rather, our human tester and a frontier-model agent have never taken a single bait: there were two interactive sessions and eighteen probes on display, none of which were touched. Both were caught by the injection path rather than by a probe. The middle of the range is the only range in which we have corroborating evidence for our gain of 7.0 points. The attractiveness of a planted item can be measured \cite{kahlhofer2024honeyquest}, and it is a natural next step to calibrate our probes to a human panel. In the end, this narrows the mechanism without removing it.

\paragraph{What if the attacker is aware of the probe?} What happens once the adversary learns to ignore probes is an inescapable question. If you give an additional action it will raise the divert point, and an attacker who maintains the belief in the band and never bites will be probed for as long as possible instead of being diverted. This is answered cohesively by the pricing without adding another term. If a session is asked the question $n$ times, it has already answered it. Its expected information is therefore discounted by $(1-\beta_a)^n$, that is the probability that a hostile client refuses that many times consecutively. As this discount falls, probing ceases to be the most economical move and the rule approaches the two-action comparison it would have with no probing. It is an asymptotic guarantee and not a per-session guarantee. At $n = 0$ the discount is exactly 1, so all the bands above are unchanged.

\paragraph{Limitations.} Four, in order of importance. First, all our traffic is generated, so all our rates refer to our traffic and would need to be measured again for real traffic; the calculation and the randomised design are independent of that. Second, we tune and test on one application, and the locked detector is still working in front of another, totally different application, but the probes themselves would have to be rewritten. Third, the number of people who have tried the fake site is only four. Fourth, the bite rate is based on a notion of curiosity that no human we have observed has yet borne out.

% 6 conclusion 
\section{Conclusion}
Passive defence requires the defender to wait for evidence, and that leaves a dilemma. We have demonstrated that, in fact, the defender can generate the evidence by sending a small, invisible probe in a reply. The value of the information provided by the probe determines when to insert the probe, not a threshold set by the user. Our measurements confirm this: The gain is seen only when the detector is really uncertain, and a randomised holdout within the probing system shows that the probe caused the improvement. There was no loss of harmless session in 99 runs. What is left is to test the idea with real traffic and real attackers.
